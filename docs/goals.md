# Goals and acceptance criteria

nsh-microphone records audio to a file or an in-memory stream for Native Shell apps: voice notes and level meters. Not speech-to-text.

The reference behavior cited below was read from the checkouts in `.refs/` on 2026-11-09: Flutter `record` (`record/lib/src/record.dart` and `record_platform_interface`), `react-native-audio-api` (`core/AudioRecorder.ts`, `types.ts`, `system/types.ts`), and `cpal` (local master is 0.19.0; the pinned dependency is 0.18.2, whose published `Error`/`ErrorKind` surface and `Stream::pause`/`play` were verified on docs.rs).

Nothing here is Done. Every test named is Authored: the code and the test exist, and the repo's CI has not run because this task may not commit or push (AGENTS.md: GitHub Actions compiles and tests everything). The criteria below state what CI will prove; `docs/parity.md` flips its rows to Done after the first green run.

Rust test names are in `crates/nsh-microphone/tests/`. TypeScript tests are in `packages/nsh-microphone/tests/`.

## Goals

- One recording API in two deliverables that stay in lockstep: `crates/nsh-microphone` (library `nsh_microphone`) and `packages/nsh-microphone` (TypeScript). Same API names, same behavior, every behaviour tested in both languages.
- The API follows the references: the recorder methods and `RecordConfig` from Flutter `record`, the permission vocabulary ("granted" / "denied" / "undetermined") from react-native-audio-api, and the encoder strings from `record`'s `AudioEncoder` plus Vorbis, which react-native-audio-api's `FileFormat.VorbisWebm` carries.
- Platform split: one Apple layer (an AVAudioEngine input tap) serves iOS and macOS; Android records through `AudioRecord` over JNI; Windows and Linux use cpal 0.18.2; the web is an unsupported target answering `ERR_MICROPHONE_NOT_AVAILABLE`.
- The layout mirrors SuperNSH/biometrics exactly: a Cargo workspace with one crate, a sibling `packages/` TS package, `docs/`, and the `site/` status page. No demo app.
- The crate doc's promise is the engineering rule: each call resolves exactly once — success, a coded failure, or a cancel.

## Error model

`ErrorKind` is `#[non_exhaustive]`. The eight codes are the stable contract: apps match on the strings, and the TypeScript `RecorderError.code` carries the same eight. Each message is one sentence, the same wording in the TS `MESSAGES` map.

| Kind | Code | Message | Covers |
|---|---|---|---|
| `NotAvailable` | `ERR_MICROPHONE_NOT_AVAILABLE` | Microphone recording is not available on this device. | the web target (every method); every call on a disposed recorder; no input device (cpal `default_input_device()` returning `None`); cpal `ErrorKind::DeviceNotAvailable` and `HostUnavailable` |
| `PermissionDenied` | `ERR_MICROPHONE_PERMISSION_DENIED` | Recording was refused. Allow microphone access in the system settings. | record's `hasPermission` returning false; react-native-audio-api's `PermissionStatus` `'Denied'`; permission still not granted after the one request; cpal `ErrorKind::PermissionDenied` (microphone privacy settings) |
| `Cancelled` | `ERR_MICROPHONE_CANCELLED` | The operation was cancelled. | a dismissed OS permission prompt (the Android layer reports the dismissal; record and react-native-audio-api surface the same event as a denial); a backend answering `Err(Cancelled)`. A user `cancel()` resolves `Ok(())`; this code marks refused prompts and backend cancels |
| `InProgress` | `ERR_MICROPHONE_IN_PROGRESS` | A recording is already running. Stop or cancel it first. | record's platforms end the running take and start a new one — Android and Darwin both document `start()` as "next take"; our gate is what refuses, before the backend is touched |
| `InvalidState` | `ERR_MICROPHONE_INVALID_STATE` | The recorder is in a state that does not allow this call. | pause, resume, stop, cancel or amplitude in the wrong state. record serializes calls through a semaphore and lets each platform throw its own error; we refuse with one code |
| `InvalidArgument` | `ERR_MICROPHONE_INVALID_ARGUMENT` | An argument is empty or not allowed on this platform. | zero sample rate; zero or more than two channels; zero bit rate on a compressed encoder; a blank file path; an unknown encoder name on the NSH surface; cpal `ErrorKind::InvalidInput` |
| `FormatNotSupported` | `ERR_MICROPHONE_FORMAT_NOT_SUPPORTED` | The encoder or format is not supported on this platform. | `is_encoder_supported` answering false at start; cpal `ErrorKind::UnsupportedConfig` (0.18 folds the classic format-not-supported / config-invalid kinds into `Error`); react-native-audio-api's `NotSupportedError` when the system encoders cannot encode the requested format |
| `Backend` | `ERR_MICROPHONE_BACKEND` | The platform's audio service failed. | cpal mid-stream errors (`ErrorKind::BackendError`, `StreamInvalidated`, `Other`) with `status` where the host gives one; record's `PlatformException` from the method channel; react-native-audio-api's `onError` (`recorderError`) events and `Result` `{ status: 'error', message }`; AVAudioSession `OSStatus` and JNI exceptions in the native layers |

The mapping happens in the platform layers (`src/platform/*`), which put the platform's numeric code in `RecorderError::status()` where there is one.

## Edge cases

| Edge case | How the references handle it (record / react-native-audio-api / cpal) | Rust test | TypeScript test |

| Start while a recording runs | record's Dart layer only serializes calls (a semaphore); the platforms end the running take and start a new one (Android and Darwin both treat `start()` as "next take"). ## Out of scope

- Speech-to-text. This library records audio; transcription is another library's job (the crate description says so).
- Device and emulator runs in CI. AGENTS.md forbids building or testing on developer machines, and CI has no devices; device behavior stays manual for maintainers (the Platform only rows above).
- Demo app. `examples/demo` and a package `App.tsx` are deliberately omitted; this repo's extra is the `site/` status page, recorded in `docs/decisions.md`.
- Streaming over the native Rust-TSX bridge in NSH 0.4.0. The NSH surface is file-output-only: `NativeRecorder.start` refuses a stream output with `ERR_MICROPHONE_INVALID_ARGUMENT`, and `rust.ts` refuses it on the TypeScript side. Chunk streaming is authored over `FakeBackend` (Rust) and `memoryBackend` (TypeScript); `docs/parity.md` documents the gap.
